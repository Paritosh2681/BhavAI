# BhavAI — Render + Supabase Deployment Runbook

This guide covers deploying BhavAI with **Render** (Static Site for React/Vite + Web Service for Express API/MCP), **Supabase** (PostgreSQL), and **PayPal Sandbox**.

> **Important:** Local Sandbox transactions stored in your local embedded PGlite database (`data/bhavai.db`) are **not** automatically transferred to Supabase. Your fresh Supabase database starts empty (unless you explicitly enable `DEMO_MODE=true` for demo seeding).

---

## 1. Supabase Setup & Session Pooler

1. Create a new project in **Supabase**.
2. Open **Project Settings -> Database -> Connection string -> URI** and select **Session pooler** (port `5432`, e.g. `postgresql://postgres.<project-ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres`).
   - Do **not** use Transaction Pooler (port `6543`) for `pg.Pool` unless configured for transaction pooling.
   - `apps/api/src/db/index.ts` automatically enables `ssl: { rejectUnauthorized: false }` when `DATABASE_URL` contains `supabase.co`, `supabase.com`, or `sslmode=require`.

### Migration Order
1. **`001_init.sql`** — Runs automatically on every `bhavai-api` startup via `migrate()` in `apps/api/src/db/migrate.ts` (idempotent `CREATE TABLE IF NOT EXISTS` + additive `ensureColumn` checks).
2. **`002_rls.sql`** — Enables Row Level Security and creates owner/participant policies using `auth.uid()::text`. It is now idempotent (`DROP POLICY IF EXISTS` before each `CREATE POLICY`):
   - Either set `APPLY_RLS=true` on `bhavai-api` (safe across restarts), **or**
   - Run `database/migrations/002_rls.sql` once in the **Supabase SQL Editor** after `bhavai-api` completes its initial boot.

## 2. Render Blueprint Setup (`render.yaml`)

1. Push the repository to GitHub (never commit `.env` or secrets).
2. In **Render Dashboard**, choose **New -> Blueprint** and select your repository. Render reads `render.yaml` and creates two services:
   - **`bhavai-api`** (`runtime: node`, builds `@bhavai/api`, starts `node apps/api/dist/index.js`, health check `/health`)
   - **`bhavai-web`** (`runtime: static`, builds `@bhavai/web`, publishes `apps/web/dist`)

### Post-Deployment Hostname Validation (Render Rewrites)
Render Static Site `routes` require static `destination` URLs (`render.yaml` uses `https://bhavai-api.onrender.com/...`).
- After `bhavai-api` deploys, check its actual `onrender.com` URL in the Render Dashboard.
- If Render assigned a suffix (for example `https://bhavai-api-xxxx.onrender.com`), update the 4 rewrite `destination` entries in `render.yaml` (`/api/*`, `/mcp`, `/mcp/*`, `/health`) to match that exact hostname and redeploy `bhavai-web`.

## 3. Environment Variables

### `bhavai-api` (Server-Side Only — Secrets Protected)
| Variable | Type | Value / Notes |
|---|---|---|
| `NODE_ENV` | Public config | `production` (set in `render.yaml`) |
| `PORT` | Public config | `4000` (set in `render.yaml`) |
| `DATABASE_URL` | **Secret** | Supabase **Session Pooler (`:5432`)** URI |
| `JWT_SECRET` | **Secret** | Auto-generated by Render (`generateValue: true`) |
| `COOKIE_SECURE` | Public config | `true` (set in `render.yaml`) |
| `APP_URL` | Public config | Deployed frontend URL (e.g. `https://bhavai-web.onrender.com`) |
| `FRONTEND_URL` | Public config | Deployed frontend URL |
| `CORS_ORIGIN` | Public config | Comma-separated allowed frontend origin(s) |
| `DEMO_MODE` | Public config | Keep `false` in production (set in `render.yaml`) |
| `PAYPAL_BASE_URL` | Public config | `https://api-m.sandbox.paypal.com` (Sandbox) |
| `PAYPAL_CLIENT_ID` | App identifier | PayPal Sandbox REST App Client ID |
| `PAYPAL_CLIENT_SECRET` | **Secret** | PayPal Sandbox REST App Secret |
| `PAYPAL_WEBHOOK_ID` | **Secret / Config** | Webhook ID from PayPal Sandbox for deployed URL |
| `GEMINI_API_KEY` | **Secret** | Optional; omit to use deterministic `POLICY` fallback |
| `GEMINI_MODEL` | Public config | `gemini-2.5-flash` (set in `render.yaml`) |
| `MCP_API_KEY` | **Secret** | Optional shared key for MCP |
| `APPLY_RLS` | Public config | Optional `true` to apply `002_rls.sql` on boot |

### `bhavai-web` (Static Site — Never Put Secrets Here)
| Variable | Value / Notes |
|---|---|
| `VITE_API_URL` | **Leave unset** when using `render.yaml` same-origin rewrites (`/api/*` -> `bhavai-api`). Keeping it unset sends browser requests same-origin so session cookies work without cross-site `SameSite` issues. |

## 4. PayPal Sandbox Webhook Registration

1. Open **PayPal Developer Dashboard -> Sandbox -> Apps & Credentials -> your Sandbox app -> Webhooks -> Add Webhook**.
2. Set **Webhook URL** to `https://<your-bhavai-api-hostname>/api/webhooks/paypal`.
3. Subscribe to the exact 4 events handled by `apps/api/src/services/orders.ts`:
   - `CHECKOUT.ORDER.APPROVED`
   - `PAYMENT.CAPTURE.COMPLETED`
   - `PAYMENT.CAPTURE.DENIED`
   - `PAYMENT.CAPTURE.REFUNDED`
4. Copy the generated **Webhook ID** into `PAYPAL_WEBHOOK_ID` on `bhavai-api` in Render.

## 5. Post-Deployment Verification Checklist

1. **Health:** `GET https://<your-web-or-api-url>/health` -> `200 OK`, `database.ok: true`, `database.mode: "postgres"`, `paypal.configured: true`, `paypal.environment: "sandbox"`, `paypal.webhookConfigured: true`.
2. **Public Config:** `GET https://<your-web-url>/api/public/config` -> `demoMode: false`, `paypal.configured: true`, `paypal.clientId` present, no secrets exposed.
3. **Auth & Catalog:** Sign up / sign in via UI, verify `Set-Cookie` works over HTTPS, and confirm product catalog loads.
4. **Negotiation & Orders:** Run a negotiation, confirm deal, and verify PayPal Sandbox button renders for USD cross-border orders (and India manual settlement works for INR domestic orders).
5. **MCP:** `POST https://<your-web-url>/mcp` (`tools/list`) returns 20 tools; protected tools reject unauthenticated callers.
6. **Analytics:** Open Seller Analytics and verify AG Grid tabs and CSV export load cleanly.

---

## 6. Rollback & Troubleshooting

- **Rollback:** Use Render Dashboard -> **Deploys -> Rollback to previous deploy** on `bhavai-api` or `bhavai-web`. Never drop Supabase tables on rollback.
- **502 / 404 on `/api/*` from frontend:** Verify `render.yaml` rewrite destinations match the exact `bhavai-api` hostname.
- **Cookie not persisting after login:** Ensure `APP_URL`, `FRONTEND_URL`, and `CORS_ORIGIN` match the exact `https://` frontend URL and `VITE_API_URL` is unset (same-origin).
- **Database SSL / pooler errors:** Confirm `DATABASE_URL` uses Supabase **Session Pooler (`:5432`)** and includes `supabase.co` / `supabase.com` or `?sslmode=require`.
